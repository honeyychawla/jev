# One-shot prompt to rebuild Emote

Copy the prompt below into your coding assistant. It describes the app's behavior and design; generated code, model results, and native emoji appearance can vary. Clone this repository for the exact implementation.

```text
Build a complete, small local web app called Emote. It turns whatever I type into relevant emoji suggestions using TypeSafe AI's actual Jev model through OpenRouter. I mean the company TypeSafe AI and its System One models, not merely type-safe TypeScript. Reference: https://typesafe.ai/blog/introducing-system-one-models-and-jev.

Make the interface professional and minimalist, like a clean Google search page: a white background, generous empty space, a small “emote.” wordmark, and one centered rounded search field. Put suggested emojis in a simple row beneath the field. Keep “All emoji” and a settings gear small and unobtrusive. Avoid chat bubbles, dashboard cards, gradients, giant marketing headings, and decorative AI branding. Use native emoji glyphs so it feels like the user's keyboard. Make the layout work on desktop and mobile without horizontal scrolling.

Scatter a decorative selection of emoji into a slightly rotated, overlapping pile along the bottom of the viewport. When I type and relevant suggestions arrive, those emoji should visibly rise out of the pile, travel the full distance to the suggestion row, overshoot slightly, and settle into place. When I delete any text, immediately drop the displayed suggestions back to the bottom with gravity-like acceleration and a small bounce. Clearing the field drops everything. If the remaining text still has matches, fresh results may rise again after the typing pause. When the meaning changes, old matches fall while new matches rise. Keep each glyph continuous during a flight: hide its stationary copies so there are no duplicates or jumps. Handle rapid typing, deletion during a flight, changing direction midair, reordered results, and resizing. Respect prefers-reduced-motion by showing results instantly and skipping flights. Keep animation decorative and nonblocking; the input must stay usable.

Use React, TypeScript, and Vite for the frontend and an Express TypeScript backend, served together on http://127.0.0.1:5173. Use the official @typesafe-ai/sdk with the OpenRouter base URL https://openrouter.ai/api and Jev model jev-1.13 by default, configurable with TYPESAFE_MODEL. Use the SDK's System One Choice API, not an unrelated chat-completions model. Verify the provider's documented integration. If access or the model is unavailable, show an honest, useful error rather than claiming a successful AI result.

Use the complete Emojibase 18 dataset, including flags, professions, joined sequences, gender variants, and skin tones. Make every emoji reachable; do not limit inference to a tiny handpicked list. For efficient selection, first rank catalog-derived categories with Jev Choice, then rank emoji in the top six categories using no more than 240 options per question. Combine scores, collapse redundant skin-tone families, and show up to eight results. Also provide a searchable full emoji picker with categories and a skin-tone switch.

Debounce inference by about 450 milliseconds. Cancel obsolete requests and ignore stale responses. Keep previous suggestions visible while additional text is being processed, but drop them immediately on deletion. Bound the backend cache to 100 results with a five-minute lifetime. Limit concurrent requests to four and requests to 90 per minute. Clicking an emoji inserts it at the cursor without losing input focus. Support Enter to search, Escape to clear, a clear button, Copy text, accessible labels, keyboard controls, loading feedback, and useful retry actions.

Let me add my own OpenRouter API key from Settings using a masked field and a “Save & test connection” button. Validate it on the backend with OpenRouter and a small real Jev request before saving. Keep an existing key untouched when validation fails. Store the key only in a local .env file with restricted permissions, clear the field afterward, and offer “Test saved key.” Never send the saved key back to the frontend, put it in browser storage, log it, expose it through Vite, or commit it. Include a blank .env.example and ignore .env and its temporary files in Git. Show the actual local .env path for manual setup. Reload key and model changes without a server restart. Distinguish a detected key from a successfully tested connection. Without a key, offer a clearly labeled local keyword preview.

Bind the server to loopback only, validate requests with Zod, and protect the key-saving endpoint with same-origin checks and an app-specific request header. Explain in the README that settled drafts go to OpenRouter/TypeSafe when AI is enabled, each user supplies their own key and credits, and this is a local app rather than a public hosted service.

Deliver the finished runnable project, a lockfile, clear cross-platform installation instructions, and a macOS double-click launcher. Use npm ci and npm run dev for setup, and provide build, start, backend-test, and browser-test scripts. Add meaningful tests for the real SDK request shape using mocked transport, key handling, stale results, insertion at the cursor, the full picker, mobile layout, rise-and-fall animation, rapid reversals, and reduced motion. Automated tests must use fake keys and mocked provider responses. Run the build and tests, inspect the actual interface, and fix failures before handing it over. Never invent a successful live API check if no working key is available.
```
