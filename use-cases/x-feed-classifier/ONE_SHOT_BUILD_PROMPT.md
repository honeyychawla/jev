# Sift — an AI discovery filter for X

Copy this entire prompt into your coding assistant:

```text
Build me a complete Chrome extension called Sift, powered by TypeSafe AI’s Jev model through OpenRouter, that works directly on my X feed while I scroll. I am an AI tinkerer who likes learning about AI, exploring new tools and releases, understanding approachable explanations, trying useful workflows, and discovering related topics. Help me decide which posts are worth exploring and which are irrelevant or empty bait. Keep it a simple feed extension with a small toolbar popup rather than a separate dashboard or replacement feed.

On each post, show one clear, reasonably sized emoji in the top-right corner with its confidence directly underneath: thumbs up for Explore, thumbs down for Skip, and a thinking face for Unclear. Keep the normal X layout intact. Do not add tiny text strips, push the post sideways, obscure the native post menu, or overlap content. The default should be just the emoji and confidence. Clicking the marker can reveal a concise explanation, the available evidence, and Useful to me or Not for me feedback. Offer optional highlighting, dimming, or crossing out in Settings. Turning the extension off must remove every added marker and style immediately.

Make the popup minimal, readable, and correctly sized: an On/Off toggle, a clear Connect Jev control, and access to Settings. Keep it usable in Chrome’s actual action popup, not only in a full browser tab. Prefill an editable profile describing my AI-tinkerer interests and allow adjacent topics. Beginner explanations, short model announcements, practical demos, honest product promotion, robotics, automation, and useful AI-adjacent ideas can all be worth exploring. Do not reduce relevance to technical depth or a few keywords. Require stronger evidence to skip than to recommend exploring.

Use my OpenRouter API key, not a direct TypeSafe key. Start with typesafe/jev-1.14 and verify OpenRouter’s official System One request format before implementing it. Provide a masked key field, a link to obtain an OpenRouter key, Test & connect, clear connection status, Disconnect, and a suitable optional host-permission request from a user click. Keep credentials in trusted extension storage, inaccessible to content scripts or page scripts. Default to session-only storage; remembering the key locally must be an explicit choice. Do not sync keys, expose them in logs, reuse a direct-TypeSafe credential, or export browser cookies.

Before Jev is connected, show a connection-needed marker and no fabricated confidence. If optional local keyword estimates are offered, keep them off by default and label them clearly as local estimates. Use actual Jev decisions to assess whether to explore, skip, or remain unsure, plus relevance, discovery value, empty bait, missing context, and a main reason. Confidence must correspond to the displayed action; do not borrow a percentage from an unrelated score when a conservative rule changes the verdict.

Read only the visible post text, quoted content, link previews, and image descriptions needed for the decision. Exclude author identity, handles, engagement counts, private messages, and unrelated page content. Optional image analysis may send at most two resized post photos or video posters after explicit media permission. Be honest that this does not watch full videos, hear audio, fact-check claims, or browse linked pages. If the evidence is insufficient, choose Unclear instead of dismissing an unseen video as irrelevant.

Let me correct recommendations and reset learned preferences. Store a small bounded set of corrections locally and include a few relevant examples in later Jev requests; explain that this personalizes context rather than retraining model weights. Cache matching judgments, invalidate them when relevant profile or evidence changes, limit requests and concurrency, and make API costs and failures understandable. Pausing should cancel outstanding work where possible. Handle newly inserted and recycled posts, slow responses, retries, and navigation without duplicate badges or layout shifts. Exclude private messages, compose, notifications, account settings, login, and other sensitive routes.

Test the real extension in isolated browser profiles with mocked OpenRouter responses and controlled X-style posts. Cover the native popup, connection flow, permission configuration, three verdicts, confidence display, missing video context, corrections, media opt-in, on/off restoration, narrow screens, recycled posts, API failures, and private-route exclusions. Keep simulated results clearly identified and do not claim live model accuracy without testing with a real configured key. Deliver a clean ready-to-load extension and ZIP, then give beginner-friendly steps for Load unpacked, choosing the correct folder, entering an OpenRouter key, refreshing X, and updating the same installation folder later.
```
